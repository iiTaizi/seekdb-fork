# 赛题三：异步 AI 列操作指南

## 1. 基线与边界

2026-11-03 用户要求优先完成第二、三题，允许在既有 `/var/tmp/seekdb-kernel-exercises-20261102` 继续验证；同时监控宿主 C 盘和 Linux 内存，磁盘低于 25 GiB 时暂停新增大写入并准备 D 盘后续输出，不迁移或注销 WSL。旧题一目录只读，不扩展数据库操作授权到其他目录或旧实例。

分支 `feat/ai-columns` 基于题目一检查点 `93aed587c9043961f9623df4bd6ce7560520abdc`。仅 MySQL、sync_mode='async'，不支持 AI 列链式依赖。复用原生 AI 函数和 Provider 校验，后台调度不得绕过 SQL、事务及索引机制。

当前官方固定比赛分支未找到题面列出的 AI 列测试和 Mock。用户允许独立本地故障服务；必须标注为本地回归，不声称官方通过。题面标称六项但表格分为五个模块，覆盖全部明确要求。

## 2. DDL 与类型

先加入 CREATE/ADD/MODIFY AI COLUMN、SHOW AI COLUMNS 和 RETRY 解析，再接入 Resolver 和 Schema。保存表达式、普通列依赖、配置、定义版本及隐藏状态。只允许合法 AI 根调用和可解析的普通列表达式；拒绝循环/链式依赖、非法选项、同步模式和维度冲突。普通业务写入只能省略 AI 列或指定 DEFAULT。

结果列采用真实声明类型；为目标类型补充输出格式提示，写回前验证 JSON、数值、日期和 VECTOR。定义变更后旧请求作废，已有行进入重算流程。

## 3. DML 与持久化任务

数据修改、旧结果失效、逐列请求标识和任务创建同事务。业务提交前不访问模型；回滚不能留下任务或调用。依赖列/主键变化触发，其他列更新不触发；删除清理任务，无显式主键时使用内部行键。

任务保存类型化行键、不可混淆的行身份、输入快照、定义版本、逐列请求 token 和任务组。删除后相同主键重新插入不能继承旧身份。输入快照使用类型化序列化，不通过拼接业务值生成 SQL。

## 4. 调度、恢复及发布

后台服务在提交后领取持久化任务，使用领取租约恢复中断；HTTP 期间不持有业务行锁。模型输入来自提交版本的快照。后台求值通过现有模块接口，避免引入反向模块依赖。

同一行同次变更的 AI 列分组处理，分别保留每列重试/状态/结果。组内所有有效列达到终态后，在一个事务中发布：成功 READY，失败 FAILED。每列写回核对行身份、请求 token、定义版本和领取归属；失效列跳过，不能阻止同组仍有效列发布。

## 5. RETRY 与严格读取

自动重试次数有上限，记录可诊断错误。手动重试支持状态和业务条件，可重新生成 READY 行；未加引号 status 是状态伪列，反引号表示业务列。

默认 PENDING/FAILED 的结果为 NULL，状态独立存储。严格读取在同一语句快照检查引用 AI 列的整列就绪情况；WHERE 仅选就绪行仍不能绕过。SELECT/UPDATE/DELETE 均检查，普通列和其他全就绪 AI 列不受影响。

## 6. 向量与索引

失效时通过正常 DML 把旧结果置空并维护索引，写回通过正常 DML 增加新向量。不得在业务事务之外直接删改向量索引。覆盖生成、HNSW/VSAG 检索、依赖更新、回滚和删后重插。

## 7. 本地故障服务与验收

服务提供确定性协议、可控延迟、乱序、429/5xx、断连、响应丢失以及实际请求日志，不按比赛模型名或固定主键分支。先测正常路径，再测事务回滚零调用、最新请求胜出、分组发布、定义变更、并发领取、进程重启和手动重试。

构建、实例和日志使用本轮 WSL 专属目录，旧数据库不升级。内部系统元数据及测试 DDL 沿用已确认的范围授权。当前阶段：状态协议、DDL/Schema、业务触发、后台生成和条件RETRY已通过第10节列出的本地验证；严格读与向量索引已有本地通过回执；最终组合回归及崩溃/超时恢复仍待验证，不能视为整题完成。

## 8. 实施数据流与不变量

任务采用与业务行同存的隐藏 outbox 元数据，包含各 AI 列当前输入快照、请求序号、定义版本、任务组、阶段及领取租约。它是持久化任务，不是仅内存通知：正常 DML 同事务写入结果失效和 outbox；回滚没有任务，删除自动移除行及任务。后台只扫描已提交数据。结果仍是真实声明类型的列，走正常 DML 和索引路径。

隐藏元数据保留类型化输入和类型化行键；行身份由新插入时独立生成的随机 token 区分，同主键删除再插入不能复用身份。单行递增请求序号用于分组。重新触发某一列只替换该列当前请求，其他列及其所属旧组仍可完成；组发布只包含仍有效的成员。

先实现有界状态编解码及纯状态转换，再接 Schema/Resolver/DML 和后台服务。任何阶段性单测都不代表 SQL 已接通。阶段有 QUEUED、CLAIMED、SUCCEEDED、EXHAUSTED、PUBLISHED，以及等待补齐参数的 NEEDS_INPUT；对外状态在组发布前仍为 PENDING，发布后按结果为 READY 或 FAILED，成功 NULL 也必须是 READY。

领取和完成必须在数据库 compare-and-swap 更新中使用：对照旧 outbox 原始字节及行身份，校验列 ID、请求序号、定义版本、领取 token 和租约期限。状态函数返回的新对象不能自行构成事务保证。HTTP 在领取事务提交后执行；调用结束后再次读行校验，组内终态结果与隐藏状态在一个事务中发布。

每行最多 16 个 AI 列，每份任务快照最多 4096 个输入值，序列化隐藏状态最多 1 MiB。超限返回错误，不静默截断；禁止持久化指针型扩展对象和未物化 LOB 定位器。解码先检查长度和集合计数，再分配，失败不发布半份状态。租约恢复计入实际尝试次数，最多 max_retries+1 次，不能无限重复。

组发布后清除输入快照和暂存结果，保留请求/定义版本及最终状态；正常结果只存于结果列。发布调用方必须先取得暂存结果，再在同一 CAS 事务中写结果列和已清理的 outbox。主键变化时轮换行身份并重新触发全部 AI 列，避免旧行键和旧请求继续写回。

本地 SDK 初始化的 `.deps` 清单仅在源码快照中规范化 CRLF 为 LF，以复用题目二已验证的缓存指纹；先逐字验证规范化后等于题目二清单，保留 `logs/ai-columns-sdk-profile-normalization.json`。仓库清单及依赖版本不改。初始化 01/02 为主动中止记录，03 为退出 0，不把中止计为成功。

定义协议单独保存原始 SQL 表达式、AI 根函数类别、维度、重试上限和排序后的普通列依赖 ID。持久化形式带版本前缀，负载使用十六进制编码，避免二进制序列化字节违反系统元数据 VARCHAR 的字符集约束。编解码校验长度、计数和剩余字节；列 ID 重映射先建立完整无冲突的新映射再发布，不能静默遗漏依赖。该协议接入实际 Schema 之前仅计为值类型实现。

Schema 使用独立的 ai_column_info 字段保存定义，不挪用普通默认值或用户注释。同步扩展 ObColumnSchemaV2 的拷贝、序列化、内存计数，以及 __all_column 和历史表的生成定义、写入和读取路径。AI 结果与内部 outbox 使用目前未分配的列标志位 4/5，普通默认值仍是 NULL。定义版本使用列 Schema 版本；重映射列 ID 时同时重映射协议中的依赖。只在授权的新实例创建这份内部 Schema，不升级已有数据库。

表达式保留定义时的 SQL mode，重新解析时恢复该模式，防止 NO_BACKSLASH_ESCAPES 等设置改变常量。业务 DML 在新行值上计算 AI 根函数的参数并保存类型化参数快照，计算过程不调用模型；后台只把参数快照交给原有 AI 根函数，避免在外部请求前重新计算依赖于会话或时间的普通表达式。普通列依赖 ID 用于触发判断，与模型参数位置分别处理。

`SHOW AI COLUMNS FROM table` 沿用普通 SHOW COLUMNS 的权限检查和六列输出，只返回 AI 列；Extra 给出 AI COLUMN 表达式及 WITH 配置。`SHOW CREATE TABLE` 也打印 AI COLUMN 定义并隐藏内部 outbox，不把 AI 定义打印成 DEFAULT。SHOW 的 AI 标志单独占位，不与既有 FULL/EXTENDED 位混用。

## 9. 后续 DML、后台与严格读取接线

- SQL Resolver 在现有 INSERT/UPDATE 的列转换和赋值处理中追加内部 outbox 表达式；只处理真正涉及的 AI 列依赖/主键/显式 DEFAULT。无关赋值不追加任务或清空结果。AI 结果失效用原生 NULL 赋值，向量索引随普通 DML 更新。
- 内部表达式保存已计算的模型参数。LOB 必须先取真实数据，JSON 保留原生类型及二进制表示；不能把定位器或指针跨事务存储。自增及无显式主键的内部行键必须在捕获时已可用，不能以空键代替。
- 后台领取成功提交后，使用原生常量 AI 表达式求值并复用题一 Provider/校验。HTTP 不在业务事务或业务行锁内。结果必须先按声明类型严格转换，组内全部终态后一次正常 DML 写结果和状态；每次 CAS 失败都重新读取并验证。
- 内部写回使用专用会话保护并确保退出时恢复，用户无法通过 SQL 开启。模型执行沿用定义者权限；任务重试与 Provider 内部重试需避免叠加，真实请求次数以本地服务记录为证。
- MODIFY 定义必须在 Schema 变更事务内失效旧结果并围住旧请求，走正常 DML 移除旧索引项；不能仅靠后台最终发现新版本。ADD 已有行的快照补齐和并发 DML 也必须用请求/行身份校验。
- Schema 事务可先写 NEEDS_INPUT 状态作为新定义的围栏，后台以正常 DML 在当前行上补齐参数后才能领取；空快照不能误当作可执行任务。AI 定义变更使用原生排他表锁/Schema 检查协调并发 DML，不允许旧计划忽略新增依赖。
- 可重试失败保存下次可领取时间；等待期间不占用行锁。租约恢复和重试分别验证时间边界，重试次数始终有上限。
- 严格读取采用原生控制扫描与主计划的门控执行，先检查所有被引用 AI 列的完整表快照，再打开主计划。控制扫描共享原语句执行上下文与事务快照，不使用另一次独立 SQL 查询代替，也不允许 WHERE/LIMIT 把检查优化掉。内部追加的 AI 失效赋值不应被误当成用户读取 AI 列。

以上为接线不变量；各接口的实现和验证进度以第10节的具体构建、SQL及故障回执为准，不能由状态单测或辅助编译推断完成。

### 9.1 输入捕获表达式接口

新增内部表达式 `T_FUN_SYS_AI_COLUMN_CAPTURE`，参数依次为旧 outbox、是否轮换身份、行键数量及行键、任务数量，再为每项任务的列 ID、定义版本、重试上限、参数数量与已计算的模型参数。整数描述项必须是 Resolver 生成的常量；真实值保留原生类型。该表达式只生成 outbox，不调用模型，返回二进制 LONGTEXT；代码生成必须核对 Resolver 写入的内部标识，禁止用户直接调用内部函数生成任务。

首次插入或主键变化使用新的 128 位随机身份，行键非空且已完成原生转换。保留身份的更新必须与已保存行键一致；单次捕获生成一个任务组。表达式先计算并物化全部输入，再编码；任何错误使当前 SQL 失败，不发布半份任务。插入接线直接使用现有 column_conv 表达式，保证自增键、内部行键与入库值一致。

捕获表达式具有逐行随机性，必须在表达式属性提取和常量继承判断中标为不可折叠；预处理语句重复执行不能复用计划期间生成的行身份。后台写回的权限是不可由 SQL 设置的专用会话标志，使用作用域守卫恢复，连接重用时重置，不能以 root 或一般内部会话身份一概放行。

原生 ObSysFunRawExpr 使用需预留容量的参数数组，构造后必须先调用 init_param_exprs，再添加参数。捕获表达式按行键数和选中任务数预留有界容量；后台 AI 根表达式与类型提示包装也遵守此约定。DML 首次真实回归发现的 -4006 已定位于此步骤，不能由辅助编译成功推断构造流程正确。

堆表的 T_TABLET_AUTOINC_NEXTVAL 只是早期占位表达式，真实内部行键在原生 DML 路由后分配。隐藏 outbox 的校验与求值放在该分配之后、DAS 写缓冲之前；普通业务列仍在原步骤检查。UPDATE 在 BEFORE 触发器之后捕获新行；并行写缓存也必须在内部行键生成之后捕获。最终写入入口强制完成捕获并拒绝 NULL outbox，不能把延迟求值变成漏校验或空键落库。

用户连接直接读取隐藏 outbox 被拒绝是预期行为。任务字节、请求身份和不重排队等断言须用原生内部测试或真实请求/写回观察验证；用户可见 DML 的通过不能替代这些证据。初次基于普通 SQL 的隐藏列 MD5 检查保留为无效验证方法的记录，不能为此放开用户访问。

### 9.2 任务选择与内部 SQL 参数

内部状态表达式接收 outbox、AI 列 ID 和当前定义版本，输出 PENDING/READY/FAILED；缺少任务或版本不一致均为 PENDING，成功 NULL 为 READY。后台只选择 PENDING 行，已发布的失败不会自动重新排队。该表达式仅允许专用内部会话或 Resolver 生成的状态伪列/严格读引用，普通 SQL 不能直接调用。

后台 SQL 的业务键、原始 outbox 及结果均通过原生类型化参数绑定。可使用 seekdb 的 PREPARE/EXECUTE 与原生会话值接口传参；SQL 文本仅包含经引用的 Schema 标识符和固定参数名称，不拼接业务值。准备语句、绑定变量和连接必须在所有退出路径释放。领取与发布走正常 UPDATE 的字节 CAS，HTTP 期间不持有事务。

内部读取隐藏状态与内部直接写回分别授权：补齐任务参数使用普通 DEFAULT 更新，保留业务 DML 捕获，但其 CAS 条件仍需读取隐藏状态；领取和发布才允许直接写 AI 结果及 outbox。两种权限都只能由 C++ 作用域守卫开启，退出及会话重用时恢复。

进入触发器或存储过程的嵌套 SQL 时，通过原生会话保存/恢复流程暂时清除内部 AI 权限，防止内部写回权限传播给用户定义的嵌套语句。

内部 SQL 执行器直接迭代原生 ResultSet 并在其执行上下文内物化 LOB；该路径关闭连接层的首行预取，避免首行被丢弃，普通 read 接口保留原来的预取行为。临时绑定变量退出时恢复原值或移除，连接上不残留业务输入。

定义保存实际定义者 ID，后台按该用户当时仍有效的模型访问权限执行，不因使用内部连接而跳过 AI 权限。类型化参数组成原生 AI 根表达式求值；结果经目标列的原生严格转换校验后才暂存。AI 列调用只发起一次 Provider 请求，失败由持久化任务的 max_retries 和下次执行时间控制，防止两层重试放大调用数；普通 AI 函数保留原来的请求策略。

### 9.3 后台生命周期及资源边界

后台两个原生线程归现有 ObAiService 所有，随模块 start/stop/wait 启停，不使用应用层轮询器。每次扫描最多16行，领取租约75秒，模型单次请求沿用有界超时；领取更新提交后才执行 HTTP。一行或一表失败要留下诊断并继续其他任务，不能使后续表永久饥饿。结果发布前重新取得 Schema 并核对同组全部当前定义，定义事务围栏仍须另外实现。

输入捕获的序列化上限预留4 KiB给租约、错误码和重试时间等元数据；外部总上限仍为1 MiB。靠近边界的合法任务必须能够被领取并记录失败，不允许捕获成功后因领取 token 增长而永远无法推进。结果本身超限走有界失败状态，不能阻塞整张表。

### 9.4 Schema变更的事务围栏接线

### 9.5 RETRY的原生更新实现

`ALTER TABLE t RETRY AI COLUMN c [WHERE ...]` 在解析器中构造带专用标记的单表UPDATE，唯一赋值为目标AI列DEFAULT。Resolver先核对目标是真实AI列，再使用已有依赖捕获、结果失效和正常DML事务/索引路径，不新增外部任务机制。RETRY关键字保持非保留，普通同名列继续可用。

条件中的未引用status改为目标AI列的内部状态表达式；反引号引用的status保留为业务字段。重写前拒绝用户直接指定隐藏状态列和内部函数，内部读取权限仅包围生成条件的解析，随后恢复。生成的状态表达式有独立来源标记，执行时不需要给用户连接内部会话权限。谓词按原生UPDATE快照求值，零命中没有任务或HTTP，只有指定列与命中行获得新请求/重试计数。

新文件 `src/sql/resolver/dml/ai_column_retry_resolver.cpp` 只负责目标检查、条件语法树重写和状态表达式来源标记；语法留在既有MySQL解析器，事务和捕获复用现有代码。重写有深度与节点数量上限，错误返回SQL，不能让深条件栈溢出。
